Write the files every generated project gets, modelled closely on rustaman/strobe (copy their structure,
tone and rigour; replace project-specific content with `@@tokens@@` and directive blocks). Files live in
`templates/<group>/files/` (see CONTRACTS.md; dotfiles use a leading `_`). Add a `manifest.js` where a
file is conditional on a flag (drop `rust-toolchain.toml` unless `toolchainPin`, pick exactly one
LICENSE variant, drop SECURITY.md unless `securityMd`, AGENTS.md/CLAUDE.md unless `agentDocs`).

templates/base/files: `_gitignore`, `_gitattributes`, `_editorconfig`, `rust-toolchain.toml`,
LICENSE variants (MIT / MIT + Commons Clause like strobe's / Apache-2.0 / dual → LICENSE-MIT +
LICENSE-APACHE), `README.md` (centered header, CI and licence badges, tagline, quick start per kind,
features list driven by flags, Development section with the gates), `CHANGELOG.md` (Keep a Changelog,
Unreleased), `CONTRIBUTING.md`, `SECURITY.md`, `AGENTS.md`, `CLAUDE.md` (sections as PLAN.md describes;
"Rules the build enforces" lists only the rules whose flags are on: lints, header banner, unsafe
boundary, toolchain pin, cargo-deny, changelog; mention "generated by create-rust-app").
Workspace projects (`workspace` flag) use `--workspace` in commands and describe the crates/ layout.

templates/github/files/_github: `CODEOWNERS` (the line is `* @` followed by `@@github@@`),
`PULL_REQUEST_TEMPLATE.md`, `ISSUE_TEMPLATE/{bug_report.yml,feature_request.yml,config.yml}`,
`dependabot.yml`, `workflows/ci.yml`, `workflows/release.yml` — the shape in PLAN.md §1 with the
SHA-pinned actions listed there, `toolchain: "@@toolchain@@"`. Adapt with directives: GUI projects
(`has_gui`) add the windows-target clippy on Linux and package themes.toml in release; `kind_lib` has no
binary release — emit a manual-dispatch publish workflow instead (`cargo publish --dry-run` then publish
with `CARGO_REGISTRY_TOKEN`); `workspace` uses `--workspace` everywhere; the deny job only with
`cargoDeny`; `release`, `dependabot`, `issueTemplates`, `codeowners`, `ci` each gate their files via
manifest.js. Every generated YAML must be valid: check them by parsing (write a throwaway validator
script in your scratch space, or reason carefully about indentation) for each preset.
