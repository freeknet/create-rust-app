## Commit only what you changed

**This repository may be worked on by more than one agent at a time.**
Assume the working tree holds someone else's half-finished work, and check
`git status` before staging anything.

`git commit` commits the whole index, not just the paths you passed to
`git add`. Use `git commit -- path/to/file` so a staged change you did not
make cannot ride along. Never `git add -A`, never `git add .`, and never
`git commit -a`.

Commit subjects use the conventional prefixes `feat:`, `fix:`, `perf:`,
`refactor:`, `docs:`, `test:`, `build:`, `ci:`.

**Line endings are `.gitattributes`' problem, not yours.** Every text file
is stored and checked out as LF, including on Windows. Do not convert
endings by hand.

## Rules the build enforces
<!-- @if workspace -->

Paths below that start `src/` or `tests/` are the app crate's, under
`crates/@@appCrate@@/`.
<!-- @end -->

### Lints: no `unwrap`, `expect`, `panic!`, `todo!`, `unreachable!`, not even in tests

<!-- @if workspace -->
Denied in `[workspace.lints]` in the root `Cargo.toml`, and every crate opts
in with `[lints] workspace = true`; a new crate without that line is
unlinted. A violation is a build failure.
<!-- @else -->
Denied in `[lints]` in `Cargo.toml`, so a violation is a build failure.
<!-- @end -->
Use `?`, `let ... else`, or an explicit fallback. Tests return
`anyhow::Result<()>`, and every `assert!` carries a message. Release builds
use `panic = "abort"`, so a panic is a crash, not an unwound error.

The same block denies `wildcard_enum_match_arm` (name every variant: that
is what catches a new variant silently doing nothing), `missing_docs`,
`unreachable_pub`, and `allow_attributes`. Suppress with
`#[expect(lint, reason = "...")]`, never `#[allow]`: `expect` fails the
build when the lint stops firing, so a suppression cannot outlive the thing
it was suppressing.
<!-- @if headerCheck -->

### Every source file opens with the header banner

A ruled block naming `Module:`, `Description:` and `Dependencies:`, then a
blank line, then the module's `//!` docs:

```rust
// ============================================================================
// Module:       config
// Description:  Loads and saves the user's settings.
//
// Dependencies: serde, toml
// ============================================================================

//! The config file: every field optional, parsed independently.
```

`src/header_check.rs` walks `src/`, `tests/` and `examples/` and fails the
build for a file missing one, so a new file needs its header in the same
commit that adds it. `Module:` is checked against the path the file sits at:
<!-- @if workspace -->
`src/foo/mod.rs` is `@@appCrateSnake@@::foo`, `src/lib.rs` is
`@@appCrate@@ (library crate root)`, and `tests/x.rs` is
`x (integration test)`.
<!-- @else -->
`src/foo/mod.rs` is `foo`, `src/lib.rs` is `@@name@@ (library crate root)`,
and `tests/x.rs` is `x (integration test)`.
<!-- @end -->
Copy an existing header and fix all three fields. The banner is plain `//`,
not `//!`; the reasoning belongs in the `//!` block below it.
<!-- @end -->
<!-- @if unsafeCheck -->

### `unsafe` lives only under `src/win/`, as safe leaf wrappers

- One named, private, **safe** function per unsafe operation. The `unsafe`
  block holds that one call and nothing else.
- Every block gets a `// SAFETY:` comment stating the actual reasoning.
- Any resource with a matching close/free/destroy API gets one owning type
  whose `Drop` releases it.
- No `pub unsafe fn`, and no unsafe in tests.

`src/unsafe_check.rs` fails the build otherwise. Need a new system call?
Add a leaf wrapper next to its siblings in `src/win/`.
<!-- @end -->
<!-- @if toolchainPin -->

### The toolchain is pinned, once

`rust-toolchain.toml` pins `@@toolchain@@`, and every workflow's
`toolchain: "..."` line must name the same version;
`tests/toolchain_pin.rs` fails the build if they drift. Bump them together,
in their own commit. Never `@stable`: CI would move to each new release on
its own, and a lint that does not exist locally cannot be caught locally.
<!-- @end -->
<!-- @if cargoDeny -->

### Every dependency passes `cargo deny check`

`deny.toml` allows a fixed list of permissive licences, denies unknown
registries and git sources, and fails on known advisories. Adding a crate
under a licence not on the list is a decision, not a fix: add it to
`deny.toml` in its own commit, saying why. An ignored advisory carries a
note saying what would clear it.
<!-- @end -->
<!-- @if changelogGen & workspace -->

### `CHANGELOG.md` is generated: never hand-edit it

`cargo xtask changelog` rebuilds it from `git tag` plus conventional-commit
subjects, so an edit to a released section does not survive. Prose for a
release belongs in the GitHub release body. **Never amend or rebase a
commit after tagging it**: the tag keeps pointing at the discarded copy,
and every release range computed from it is then wrong.
<!-- @elif changelogGen -->

### `CHANGELOG.md` moves with the code

Every user-visible change adds a line under `## [Unreleased]` in the same
commit, in the section its prefix implies (`feat:` under Added, `fix:`
under Fixed). A release moves those lines under its version heading
before the tag is cut. **Never amend or rebase a commit after tagging it.**
<!-- @end -->

### Constants live with what they govern

There is no `constants.rs`. Use a function-local `const` first, then a
module-private one, then `pub` in the module that owns the concept.

## Things that are deliberate, not oversights

- **`panic = "abort"` and fat LTO in `release`.** Smaller, faster binaries;
  `release-fast` is the profile for iterating.
<!-- @if kind_lib -->
- **Errors are one `thiserror` enum.** Callers match on variants; a new
  failure mode is a new variant, not a string.
<!-- @else -->
- **`main.rs` is a thin shell over `lib.rs`.** The logic lives in the
  library so tests and examples reach it without spawning a process.
<!-- @end -->
<!-- @if clap -->
- **Exit code 2 for refused arguments.** That is the convention shells and
  scripts expect from a usage error, distinct from a runtime failure.
<!-- @end -->
<!-- @if has_gui -->
- **No console window in release on Windows**
  (`windows_subsystem = "windows"`), so failures are shown in a message
  box rather than printed to a console nobody sees.
<!-- @end -->
<!-- @if config & serde & !kind_lib -->
- **Every config field is optional and parsed on its own.** One bad value
  costs that setting, not the file, and writes go through a temp file and a
  rename so a crash mid-write cannot leave a half-written config.
<!-- @end -->
<!-- @if dependabot -->
- **Dependabot groups patch bumps only.** Under cargo a `0.x` minor bump is
  the breaking one, so it arrives as its own PR.
<!-- @end -->
<!-- @if ci | release -->
- **Actions are pinned to full commit SHAs**, with the version in a trailing
  comment. A mutable tag is a supply-chain risk; a pin moves in a reviewed
  diff.
<!-- @end -->
